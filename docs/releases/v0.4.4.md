# Plombir Git v0.4.4

This release makes the repository home page work the way GitHub's does. It
adds no migration and changes no setting, so an upgrade is a restart on the new
binaries; v0.4.3 can be started again on the same database.

## Before upgrading

Upgrade frontend and backend together using the release bundle or a build from
the release tag: the new page reads four new API endpoints. Installations
upgrading from an older release must also follow the [v0.4.3 notes](v0.4.3.md)
and the earlier notes they link.

## The repository page

- **Folders first.** Directories and submodules are listed before files, each
  alphabetically without regard to case.
- **Last commits.** Every entry shows the commit that last changed it, with its
  message and age, and the newest commit heads the list with the commit count.
  Inside a directory the history link shows the history of that directory.
- **About.** At the root, a column shows the description, stars, forks, the
  latest release and the languages of the repository.
- **Go to file.** On the repository and file pages: type any part of a path;
  `t` focuses the box; its last choice searches the code. It replaces the code
  search box of the toolbar.
- **Branches and tags.** The branch picker filters by name and lists tags too;
  the toolbar shows how many of each there are.
- **README.** A wide image or table no longer gives the README a horizontal
  scrollbar, the README is shown whole instead of in a box of its own, and an
  outline lists its headings.
- The Code button has a single caret, New file is an ordinary button, and the
  repository name link at the right of the toolbar is gone.

## Security

The outgoing mail library lettre is updated to 0.11.24 for RUSTSEC-2026-0560
to RUSTSEC-2026-0565, among them SMTP command injection through a bare line
break and STARTTLS reply injection by a man in the middle, and url to 2.5.9 for
RUSTSEC-2026-0592. Installations that send mail through SMTP should upgrade.

## Load on the server

The last commits of a directory come from a walk of its history that reads at
most 10 000 commits; the commit count stops at 100 000, the language
statistics at 200 000 tree entries and the file list at 50 000 paths. Each part
loads after the listing, so a slow walk on a large repository delays only the
commit column, which then shows the entries it reached. The answers are not
cached: every visit to a repository root runs the walk, the count and the
language statistics once.

## API

`GET /repos/{owner}/{name}/tree/commits`, `.../commit-count`, `.../languages`
and `.../files` are described in [the API notes](../api.md#repository-overview-044).
They need read access to the repository, like `GET .../tree`.

## Manual smoke checklist

- [ ] `/readyz` succeeds and the server, runner and MCP binaries report `v0.4.4`.
- [ ] A repository root lists folders before files, with a last commit on every
      row, the newest commit and the commit count above the list.
- [ ] The About column shows the description, the latest release and languages.
- [ ] `t` opens Go to file; a file opens with Enter; the last choice searches code.
- [ ] Inside a directory the path is a row of links and History shows only
      that directory's commits.
- [ ] A README with a wide image has no horizontal scrollbar.
- [ ] A private repository's overview endpoints answer `404` to an outsider.
